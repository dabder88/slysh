# Запись встречи без бота

Экран **Запись встречи** (`#/meeting`) пишет то, что слышно из колонок или наушников Windows (Zoom, Meet, Teams, браузер), и по желанию ваш микрофон. В созвон бот не входит: захват идёт локально через WASAPI loopback.

Диктофон (`#/live`) по-прежнему только микрофон. Одновременно оба режима нельзя.

## Для пользователя

1. Сайдбар → **Запись встречи**.
2. **Выход** — наушники или динамики, в которые идёт звук созвона. Если Windows уже считает Bluetooth текущим выходом, он будет первым в списке.
3. **Микрофон** — ваш голос. Чекбокс **Мой микрофон** по умолчанию включён. Системный звук пишется всегда.
4. Если наушники подключили **после** запуска Slysh — **Обновить**. Кнопка заново спрашивает Windows про выходы и микрофоны (Bluetooth, док-станция). Пока запись идёт, кнопка недоступна.
5. Перед **Записью** при необходимости включите **Определять спикеров после записи** (рядом с **Таймкоды**). **Запись** — должны появиться красная плашка «Идёт запись», таймер и обводка панели. Полоска **Система** реагирует, если в выбранном выходе что-то играет. Пока первый текст ещё не готов, показывается индикатор «Распознаём речь…». Текст расшифровки появляется в окне ниже в реальном времени.
6. **Пауза** — захват звука приостанавливается, таймер замирает, уже показанный текст остаётся. Буфер может дообработаться. **Продолжить** — запись снова идёт, новые фрагменты дописываются ниже.
7. **Стоп** — подтверждение, затем завершение. Job попадает в обычный список расшифровок. WAV: `%LOCALAPPDATA%\Slysh\recordings\meeting-ГГГГММДД-ЧЧММСС.wav`. После стопа доступны **Копировать** и **Экспорт**. Спикеры — в спойлере **Распознавание спикеров** (кнопка или авто-чекбокс перед записью). Во время «Распознать спикеров» кнопка **Остановить** в редакторе отменяет диаризацию. **Очистить экран** сбрасывает текст на этом экране для новой записи; job в списке расшифровок остаётся.

Текст появляется окнами ~10 с (переменная `GIGAAM_LIVE_CHUNK_SECONDS`, можно уменьшить до ~5 с для более частых обновлений, но качество ASR на коротких фразах хуже). При уходе с экрана и возврате обновление продолжается автоматически. Чекбокс **Таймкоды** добавляет префикс `[мм:сс]` к каждой строке в окне расшифровки.

Предупредите участников, что разговор записывается. Наушники дают меньше эха, чем колонки.

Gemini CLI на этом экране нельзя: выберите локальную или HTTP-модель.

## Ограничения

- Только Windows.
- Одна моно-дорожка: отдельных каналов «я / они» нет. Спикеров можно разметить **на этом же экране** после стопа (кнопка или авто-чекбокс) или в редакторе job. Точность ниже при нескольких удалённых участниках на одном канале.
- Пишется микс того выхода, который выбран (то, что реально играет в эти наушники/колонки), плюс микрофон.
- Bluetooth Hands-Free — отдельный микрофонный endpoint, не путать со Stereo-выходом.

## Устройство

```
#/meeting
  POST /api/meeting/start
       ├─ WASAPI loopback (wasapi_loopback.py) → системный звук
       ├─ sounddevice InputStream → микрофон (если включён)
       └─ MeetingMixer → LiveSession (16 кГц моно)
            └─ тот же _live_worker, что у диктофона (~20 с)
                 job kind=meeting, сегменты в SQLite
```

| Что | Где |
|-----|-----|
| Экран | `web/js/meeting.js`, секция `view-meeting` в `web/index.html` |
| Микшер, списки, refresh | `src/slysh/meeting_capture.py` |
| Системный звук | `src/slysh/wasapi_loopback.py` (COM, `AUDCLNT_STREAMFLAGS_LOOPBACK`) |
| HTTP | `GET/POST /api/meeting/devices\|status\|start\|pause\|resume\|stop` в `api.py` |
| Job | `JobKind.MEETING = "meeting"` |

UI-процесс не импортирует torch. Ресемпл в 16 кГц — numpy.

`sounddevice` 0.5.x **не** умеет `WasapiSettings(loopback=True)`. Системный звук открывается через Windows Core Audio, а не через PortAudio loopback. Сообщение «доступна только в Windows» показывается только если платформа не `win32`.

Список **Выход** — активные WASAPI render endpoints (GUID устройства). Список **Микрофон** — PortAudio, с предпочтением WASAPI; без Microsoft Sound Mapper и дублей MME/DirectSound.

`GET /api/meeting/devices?refresh=1` (и `GET /api/mics?refresh=1` у диктофона): `PaWasapi_UpdateDeviceList` + `sd._terminate()` / `_initialize()`, кэш микрофонов сбрасывается. Во время записи refresh возвращает 400.

Тесты: `tests/test_meeting_capture.py`.

## Если не пишется

| Симптом | Что сделать |
|---------|-------------|
| Наушников нет в списке | Подключить их и нажать **Обновить**, не перезапуская Slysh |
| Нет красной плашки после «Запись» | Смотреть красный текст под кнопками; запись не стартовала |
| Полоска «Система» пустая | В выбранном выходе должен играть звук; проверьте, что Zoom/браузер выводят в те же наушники |
| «Сначала остановите диктофон» | Стоп на `#/live` |
| Не открывается loopback | Закрыть программы с эксклюзивным доступом к аудио; не выбирать Sound Mapper |

Логи UI: `%LOCALAPPDATA%\Slysh\logs\app.log`. Ошибка открытия loopback пишется с traceback.
