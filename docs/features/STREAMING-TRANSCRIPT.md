# Поток сегментов в редакторе (файловая job)

## Поведение

При расшифровке **локального файла** (`kind=file`) сегменты появляются в редакторе **по мере готовности**, пока job в статусе `running`. GET `/api/jobs/{id}` возвращает накопленные `segments` до завершения job.

- Редактор опрашивает job ~раз в 400 ms и дописывает новые блоки в список.
- Режим **«Правка»** недоступен, пока идёт расшифровка файла.

### Локальный engine (GigaAM / Whisper)

- Декодирование медиа (`ffmpeg` → PCM 16 kHz) в **UI-процессе**.
- ASR чанками ~20 с через engine `POST /transcribe_chunk` (как у диктофона/встречи).

### Облачные провайдеры (HTTP, OpenRouter, custom, Gemini CLI)

- Файл режется на MP3-чанки (`prepare_stt_chunks`); для потока в редактор по умолчанию **~3 мин** на чанк (`GIGAAM_REMOTE_FILE_CHUNK_MS`, минимум 60 000), без потока — до 8 мин / 20 MiB.
- После каждого HTTP/CLI-ответа сегменты **дописываются** в SQLite (`append_segments`), как у engine.
- Короткий файл (один чанк) визуально как раньше: текст после одного запроса.

## Ограничения

| Путь | Поток в редакторе |
|------|-------------------|
| Локальный engine | Да (~20 с на обновление) |
| Облачный HTTP / OpenRouter / custom / CLI | Да (по MP3-чанкам, см. выше) |
| YouTube ingest | Нет (отдельный сценарий) |
| Live / meeting | Уже было (чанки в `_append_live_segments`) |

### Whisper (локально)

Для потока **не** используется engine `/transcribe_file` (цельный PCM). Whisper и GigaAM идут через одинаковые 20-секундные чанки; качество/границы фраз могут чуть отличаться от whole-file Whisper.

### Облако

Чанковая склейка может отличаться от whole-file. Более мелкие чанки (env) дают чаще обновления редактора, но больше API-запросов (лимиты Groq и др.).

## Отмена

При отмене job сохраняются сегменты, уже записанные в БД; статус `cancelled`.
