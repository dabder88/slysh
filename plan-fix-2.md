## 4. Подробные задания

### R01. Не терять редакторские изменения при диаризации

**Где:** `src/slysh/speakers.py:64–79`, `api.py:2435` и обработчик запуска спикеров.

**Причина:** `assign_speakers()` читает snapshot, а затем полностью заменяет сегменты. При ошибке/отмене восстанавливает snapshot. Проверка ревизии отсутствует; completed-задание во время диаризации остаётся доступно сохранению.

**Эксперимент:** исходный текст `OLD`; backend-заглушка во время обработки сохраняет `USER EDIT`, затем выбрасывает ошибку. После завершения в БД снова `OLD`.

**Почему исправлять:** пользователь уже успешно сохранил изменение, но оно исчезает без возможности восстановления и без конфликта API.

**Решение:**

1. Удалить восстановление полного snapshot при ошибке/отмене, если операция ещё не применяла изменения.
2. Сохранять базовую ревизию перед запуском. Применение результата выполнять одной транзакцией с проверкой этой ревизии.
3. Обновлять привязки спикеров, не заменяя актуальный текст старой копией. При несовместимом изменении структуры сегментов отклонять устаревший результат.
4. Серверный guard сохранения учитывает активную диаризацию. UI объясняет временную недоступность сохранения и сохраняет локальный черновик.
5. Проверка ревизии остаётся обязательной даже при UI-блокировке: запросы могут пересечься до блокировки.

**Проверки:** успешный результат, ошибка и отмена; в каждом случае конкурентное сохранение непосредственно перед применением результата. Проверить редактирование текста и изменение структуры сегментов. Проверять БД и HTTP, а не только backend-заглушку.

**Критерий R01:** успешно сохранённый новый текст не возвращается к старому ни при одном исходе диаризации; устаревший результат отклонён явно.

### R02. Применять ответ сохранения только к соответствующему черновику

**Где:** `web/js/legacy.js:2017–2051`, `web/js/editor.js`, обработчики `__editorMarkDraftSaved` и `__editorRefreshJob`.

**Причина:** после PATCH и последующего GET вызываются перерисовка и сброс dirty для текущего редактора без проверки задания и версии черновика.

**Эксперимент:** сохранение A задержано; редактор переключён на B, в B есть новый текст. Ответ A устанавливает текст A в текущую область и `dirty=false`.

**Решение:**

1. При сохранении захватить `job_id`, ревизию сервера, номер версии локального черновика и отправленный текст.
2. Черновики и состояние сохранения хранить по `job_id`, не только в общих переменных.
3. Обновление общего списка заданий допустимо после любого актуального ответа. Перерисовка редактора разрешена только при совпадении задания и версии черновика.
4. Снимать dirty только для той версии, которая действительно сохранена. Новые правки, сделанные во время запроса, остаются dirty.
5. На 409 не подменять черновик серверным текстом; показать конфликт и сохранить оба варианта для решения пользователя.

**Проверки:** задержанный PATCH/GET; переход A→B; новые правки в A во время сохранения; два сохранения с обратным порядком ответов; 409; сетевая ошибка; переход назад к сохранённому заданию. Использовать управляемые promises, а не случайные sleep.

**Критерий R02:** ответ меняет только соответствующую версию соответствующего задания. Никакой несохранённый текст не очищается автоматически.

### R03. Включить диаризацию в общий исполнитель и адресную отмену

**Где:** `src/slysh/api.py:2645`, `batch_runner.py:362`, `engine_server.py:_OperationCancel`, `engine_client.py:cancel`.

**Причина:** запуск спикеров не резервирует local slot. `/cancel` относится к последней начатой engine-операции, а не к переданному заданию.

**Последствие:** ASR и NeMo могут пересечься на одном GPU; отмена спикеров может затронуть чужую обработку.

**Решение:** единый локальный исполнитель для ASR и диаризации; все пути, включая пакетный, получают слот. Передавать идентификатор операции/запуска в engine-запрос и отмену. Отмена ожидающей операции удаляет только её; отмена выполняющейся проверяет её идентификатор. Освобождение слота — в `finally`, после фактического завершения.

**Проверки:** ASR A + диаризация B; диаризация A + ASR B; два задания спикеров; отмена ожидающего B; поздняя отмена уже завершённого A; ошибка запуска и повтор. Заглушки фиксируют максимальное число одновременных локальных вызовов и идентификаторы отмены.

**Критерий R03:** локальный backend одновременно выполняет не более одной тяжёлой операции; отмена никогда не относится к другому запуску.

### R04. Сохранить короткий речевой хвост

**Где:** `src/slysh/chunking.py:20`, `live_buffer.py:60–75`, `tests/test_chunking.py:6`.

**Эксперимент:** 20,5 с при 16 кГц — 328000 отсчётов; в chunks передано 320000. 8000 отсчётов потеряны для распознавания.

**Решение:** передавать любой непустой остаток. Если модели нужна минимальная длина, дополнять нулями только модельный вход, сохраняя настоящую длительность. Таймкоды результата ограничивать реальным концом. Смещения считать в отсчётах/миллисекундах без целочисленного округления секунд. При pause/resume не дублировать хвост.

**Проверки:** длительности 0; 0,2; 0,999; 1; 19,9; 20; 20,5; 40,5 с; слово только в остатке; пустой и тихий хвост; pause/resume/stop. Проверять покрытие входных отсчётов и реальную короткую речь. Старый тест отбрасывания заменить тестом сохранения.

**Критерий R04:** ни один непустой участок записи не исключён только из-за длительности менее секунды; нет таймкодов за пределами аудио.

### R05. Отражать ошибки обязательных стадий пакета

**Где:** `src/slysh/batch_runner.py:378–393`, аналогичные ветки YouTube.

**Причина:** исключение экспорта/спикеров записывается в error_text, затем элемент учитывается в done; on_error не применяется.

**Решение:** результат элемента должен учитывать ASR, выбранную диаризацию и включённый экспорт. Любая ошибка обязательной стадии увеличивает failed. Для stop пакет переходит в paused с причиной и не запускает следующий элемент; continue обрабатывает остальные и завершает пакет с ошибками. Сохранять удачный текст. Повтор не должен без необходимости оплачивать/выполнять ASR заново, если требуется только экспорт.

**Проверки:** недоступная папка, заполненный диск, ошибка одного из нескольких export destinations, отказ диаризации; stop/continue; отмена; повтор после восстановления доступа; одинаковые проверки для файлов и YouTube, где стадия поддерживается.

**Критерий R05:** обязательная неуспешная стадия не представлена пользователю как полный успех; счётчики и остановка соответствуют факту.

### R06. Закрыть обход авторизации по суффиксу URL

**Где:** `src/slysh/local_auth.py:68`, `api.py:2945`, `providers.py:549`.

**Доказательство:** при включённых auth и loopback guards PUT без cookie на обычный ID получает 401, на `provider.json` достигает обработчика. ID с точкой допускается настоящей моделью провайдера.

**Границы:** middleware проверен динамически с безопасным обработчиком; изменение настоящего провайдера прослежено по коду. Условие — существующий подходящий ID и локальный отправитель, способный задать Origin. Не заявлять доказанную эксплуатацию из произвольного сайта.

**Решение:** сначала классифицировать `/api/*`: авторизация обязательна, кроме точного минимального bootstrap allowlist. Статические исключения разрешать только GET/HEAD по известным каталогам/маршрутам. Не освобождать запрос по расширению. Не ограничиваться запретом точки в ID — это оставит ошибку middleware для будущих маршрутов.

**Проверки:** без токена, неправильный токен, корректная сессия; PUT/PATCH/DELETE/POST на ID с `.json`, `.js`, `.css`, `.svg`; неизвестные пути; bootstrap; GET/HEAD статики; чужие Host/Origin; медиаплеер в настоящем WebView. API-проверку выполнить на временном провайдере и вымышленном ключе без сетевой расшифровки.

**Критерий R06:** расширение и имя ресурса не меняют требования авторизации; обычные UI-сценарии сохраняют работоспособность.

### R07. Удалить открытые секреты из резервных файлов при миграции

**Где:** `src/slysh/settings_store.py:48–51`, `providers.py:_read_stored_api_key`, миграция proxy.

**Доказательство:** после переноса вымышленного ключа в DPAPI `settings.json.bak` содержит исходный открытый ключ.

Учесть существующие `.bak` и временные файлы, не удаляя несекретные настройки. Восстановление настроек не должно возвращать plaintext. Секреты не печатать в логах.

**Проверки:** ключи всех провайдеров, custom и пароль proxy; несколько секретов; повтор миграции; повреждение основного settings; сбой записи на каждой стадии. После успеха искать только вымышленные значения во всех созданных файлах; проверить, что приложение по-прежнему получает ключ из DPAPI.

### R08. Вернуть согласованный контракт секретов

**Где:** `src/slysh/provider_reveal.py:17–28`, GET провайдеров и поля настроек.

**Факт:** GET для авторизованного UI обогащается полным ключом. В этом чате владелец выбрал «только замена»; в новых документах описан просмотр по глазику. Более позднее разрешение владельца в контексте этой приёмки не подтверждено.

**Решение по умолчанию:** GET отдаёт признак наличия и источник секрета, не значение. Поле отсутствует в изменении — сохранить; непустое значение — заменить; отдельное явное действие — удалить. При открытии настроек поле пустое. Для env показывать источник, не изменять переменную окружения.

Если владелец действительно отдельно разрешил раскрытие, приложить это решение и актуализировать контракт; не выдавать реализацию раскрытия за выполнение требования «только замена».

**Проверки:** GET с действительной сессией не содержит вымышленных ключей; изменение имени/модели не стирает секрет; замена и удаление работают; proxy и env покрыты аналогично.

**Критерий R08:** реализованный контракт совпадает с явно утверждённым требованием.

### R09. Сделать установку и первый запуск автономными

**Где:** `launcher/Slysh.c:688–694`, `dist/payload/.venv/pyvenv.cfg`, `scripts/fetch-installer-redist.ps1`, `installer/Slysh.iss`, `Slysh.bat`.

**Причина:** .venv с абсолютным build-путём непригодна после переноса; launcher удаляет её и вызывает сетевой `uv sync`. WebView2 redist является небольшим Evergreen Bootstrapper, а не полным offline runtime. BAT-путь с offline-флагом не доказывает работоспособность основного EXE.

**Решение:**

1. Не полагаться на перенесённую готовую venv. Создавать UI-окружение в конечном каталоге пользователя из закреплённого bundled Python и локального wheelhouse.
2. Поставлять полную транзитивную базу wheels, исключить необходимость компиляции sdist на компьютере пользователя. Локально собирать необходимые wheels при подготовке payload.
3. Не требовать dev-зависимости и editable build на первом запуске. Manifest базового окружения должен соответствовать lock-файлу и wheelhouse.
4. Основной launcher и BAT используют один контракт bootstrap, без скрытой сетевой ветки.
5. Включить полный автономный WebView2 runtime подходящей архитектуры; установка runtime не должна требовать доступа к сети.
6. Тяжёлые пакеты и веса остаются отдельной добровольной загрузкой. Отсутствие модели не мешает открыть UI.
7. Не повредить уже установленные engine-окружения при обновлении UI.

**Проверки:** чистые Win10/Win11 x64 без Python/uv/ffmpeg/WebView2 и без кэшей. Отключить сеть **до запуска Setup**. Установить в путь с пробелами/кириллицей; открыть UI обычным пользователем. Повторить обновление с сохранёнными данными. Зафиксировать сетевые попытки и ошибки. Тестировать именно итоговый EXE, не только payload.

**Критерий R09:** установка и открытие базового интерфейса проходят без интернета и без ссылок на компьютер сборки.

### R10. Ограничить память и сделать декодирование отменяемым

**Где:** `src/slysh/decode.py:68–145`, `live_buffer.py:43`, обработка диапазонов в API.

**Причина:** целый источник копируется, ffmpeg возвращает весь PCM через capture_output, затем создаётся numpy-копия. LiveSession накапливает pending через concatenate. Ограниченная ingest-очередь не ограничивает downstream-буфер при медленном ASR.

**Решение:** потоковое декодирование или PCM-файл с чтением ограниченных блоков; диапазон передавать ffmpeg до полного декодирования; длительность получать ffprobe; управлять subprocess и отменой. Запись на диск — источник истины для live, RAM содержит ограниченное окно. Временные файлы очищать при ошибке/отмене. Переполнение именно очереди сохранения должно быть явной ошибкой с сохранением доступного аудио.

**Проверки:** входы на 1 и 3 часа; медленный и зависший ASR; узкий диапазон в длинном файле; отмена в середине decode; нехватка диска; ошибочный файл. Измерять отдельно память модели, декодера и текста. Проверить, что увеличение длительности не увеличивает буфер аудио пропорционально ей.

**Критерий R10:** объём RAM аудиобуфера ограничен выбранным размером окна/очередей, отмена останавливает ffmpeg, выбранный диапазон и хвост сохраняются.

### R11. Ограничить ожидания и корректно завершать зависшие операции

**Где:** `src/slysh/engine_client.py:42`, `app.py:546`, жизненный цикл UI/engine.

**Причина:** управляющие запросы могут использовать timeout=None; цикл ожидания server.started не учитывает дедлайн или смерть серверного потока.

**Решение:** разделить время подключения, управляющего запроса и длительной обработки. Ожидание UI-сервера — 30 с; подключение engine — 5 с; управляющий запрос — 10 с. Для долгого ASR использовать прогресс и настраиваемый watchdog отсутствия прогресса, исходное значение 10 минут. Проверять смерть процесса/потока. Ошибка должна освобождать слот и становиться видна пользователю. Закрывать только собственные процессы, сначала штатно, затем по ограниченному дедлайну.

**Проверки:** серверный поток сразу упал; не появился порт; процесс жив, но не отвечает; cancel завис; обработка дольше обычного, но регулярно сообщает прогресс; выход во время финализации. Не убивать процессы по непроверенному PID из старого файла.

**Критерий R11:** нет бесконечного ожидания без возможности выхода; нормальная длительная обработка не обрывается из-за короткого тайм-аута управления.

### R12. Привязать single-instance к каталогу данных

**Где:** `src/slysh/single_instance.py:31`, `tests/test_single_instance.py`.

**Причина:** имя mutex постоянно — `Local\SlyshDesktopSingleInstance`. Разные каталоги данных конфликтуют, включая тесты и пользовательское приложение.

**Решение:** формировать имя из устойчивого хеша нормализованного абсолютного каталога данных. Проверить сигнатуры WinAPI для 64-битных дескрипторов и обработку ошибок. При неуспешном acquire освобождать уже созданные ресурсы. Блокировку получать до восстановления незавершённых заданий.

**Проверки:** один каталог — второй процесс отклоняется; разные каталоги — оба разрешены; release→acquire; аварийный выход; различие регистра/нормализации пути; исключение в середине acquire. Прогнать при запущенном пользовательском Slysh, не закрывая его.

**Критерий R12:** изолированный тестовый экземпляр не конфликтует с пользовательским; два владельца одного каталога невозможны.

### R13. Изолировать загрузки обновления и проверять фактический EXE

**Где:** `src/slysh/updates.py:192–199,280–309,327`.

**Причина:** check_for_updates сбрасывает общее состояние даже при загрузке. Нет operation ID; повторные потоки могут записывать один путь и менять чужую фазу. apply_update сравнивает сохранённый digest, не пересчитывая хеш текущего файла.

**Решение:** отделить найденный релиз от выполняющейся загрузки. У каждой загрузки immutable metadata и operation ID, уникальный временный путь; старые callbacks не меняют новую операцию. После проверки атомарно публиковать готовый артефакт. Перед запуском повторно хешировать файл. Прерывание и несовпадение хеша блокируют запуск.

Дополнительно проверить HTTP-редиректы: validate должен распространяться на конечный адрес и каждый переход, а GitHub-токен не передаваться произвольному asset-host. Это замечание по защите потока загрузки, а не доказанная удалённая эксплуатация.

**Проверки:** check во время download; двойной start; два разных релиза; ответы в обратном порядке; повреждение файла после ready; разрыв сети; отсутствующий digest; редирект на запрещённый адрес. subprocess запуска Setup заменить заглушкой.

**Критерий R13:** запускается только реально проверенный файл актуальной операции; старые потоки не устанавливают ready для новой загрузки.

### R14. Не публиковать неподтверждённый payload

**Где:** `scripts/build-installer-payload.ps1:243–254,282,311–349`.

**Причина:** sync без locked/no-dev, fallback на старую venv при ошибке и замена текущего payload до финальных smoke. Полученный результат может смешать новые исходники со старым окружением.

**Решение:** закрепить версии Python/uv и проверять их хеши; разрешение зависимостей только из утверждённого lock. Ошибка подготовки окружения должна останавливать сборку. Все проверки выполнять на staging до переключения. Старый успешный результат сохранять до принятия нового. Пересобирать launcher из текущего исходника, проверять exit code всех команд.

**Проверки:** недоступный пакет; повреждённый архив; ошибка smoke; занятый файл; отсутствующий ffmpeg; повторная сборка; установка в иной путь. В каждом аварийном случае старый принятый payload остаётся доступен. Сравнивать версии и manifest компонентов; не требовать побитового совпадения EXE, если инструмент добавляет timestamps.

**Критерий R14:** неуспешная сборка не выдаёт новый успешный артефакт и не уничтожает предыдущий рабочий результат.

## 7. Безопасный запуск проверок

Задавать `PYTHONPATH` на src проверяемой копии, `PYTHONDONTWRITEBYTECODE=1`; базовый pytest запускать с `-p no:cacheprovider`, временным `--basetemp` и отдельным `GIGAAM_DESKTOP_HOME`. Родитель basetemp должен существовать и быть доступен для записи. Не переносить временную инфраструктурную ошибку в список дефектов продукта.

Не запускать весь `ci_mandatory_checks.ps1` при режиме «только чтение»: он выполняет npm ci и сборку CSS. При реализации это допустимо в рабочей копии; при аудите разделять проверки и направлять артефакты за пределы исходников.

Не завершать пользовательские Python-процессы ради зелёного теста. Убирать только процессы, созданные конкретным тестом и известные по сохранённым дескрипторам.
